# PROGIT / PROTOCOLS OF ENGAGEMENT

**Version:** 1.0  
**Status:** Enforced

## 1. THE PRIME DIRECTIVE: CORRECTNESS OVER SPEED

This project is an engineering meritocracy. Our primary objective is the creation of secure, privacy-first, and technically correct code.

- **Code is Liability:** Do not commit code that you have not ruthlessly vetted.
- **Security is not a Feature:** It is the baseline. "Move fast and break things" is rejected here. We move deliberately and secure things.
- **Merit Wins:** The quality of the patch determines its acceptance. Seniority, reputation, or identity are irrelevant variables in the equation of code quality.

## 2. APOLITICAL ENGINEERING

We are builders, not activists. This repository is a workspace, not a stage for beliefs.

- **Radical Indifference:** We do not care if you have blue hair, a grey beard, or no hair at all. We do not care about your demographics, your background, or your personal beliefs. These are irrelevant to the function of a pointer or the security of a hash.
- **No Soapboxes:** While we are indifferent to your identity, we are hostile to the *politicization* of that identity within this project. Do not use issues, commit messages, or documentation to signal virtue or advance a social agenda.
- **The Engineer's Neutrality:** We treat code as a neutral tool for individual sovereignty. If you are here to fight a culture war, a religious war, or signal virtue, you are in the wrong directory.

## 3. STATE AS PROTOCOL

If this project adheres to any philosophy, it is the **State as Protocol**.

- Governance is minimal, automated where possible, and strictly functional.
- We value self-sovereignty and decentralization.
- Authority in this project stems from competence and the ability to maintain the protocol's integrity, not from social consensus.

## 4. COMMUNICATION STANDARDS

We value clarity and technical truth over comfort.

- **Be Direct:** Technical criticism is not a personal attack. If your code is described as "insecure" or "garbage," understand this refers to the *bytes*, not your *being*. Fix the bytes.
- **Thick Skin Required:** Direct, blunt, and constructive feedback is the norm. We do not sugarcoat. We expect you to defend your technical decisions with logic and data, not emotion.
- **No Bikeshedding:** Do not waste entropy discussing trivialities. Focus on the architecture, the security model, and the implementation.

## 5. DISPUTE RESOLUTION

In the event of a conflict:

1. Refer to the Code.
2. Refer to the Architecture.
3. If the conflict persists, the Maintainer's decision is final—not as a ruler, but as the primary key holder of the project's integrity.
